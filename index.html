市场现在到了哪一步？

这两年设计师 AI 工具的重点在变：早期主要是用 AI 生成图片，现在更多厂商把功能做成可复用、可管理的设计流程。 关注的问题也从「要不要用 AI 生图」，变成「怎么把设计经验整理成能反复用的方法」。

02

为什么这次和以前的生图工具不一样？

用几个类比说明 Agent 和 Skill 跟普通的生图功能有什么不同。

认知造物

唐纳德·诺曼有个观点：技术往往不是提升人的能力，而是改变任务本身。比如购物小票，把「回忆买了什么」变成「核对清单」。

设计工具也类似。对设计师来说，主要变化是工作内容：从过去从零搭界面，变成审核和修改 AI 生成的初稿。

外化链条

  • 思想 → 语言 → 书写 → 印刷
  • → 数字化 → 计算
  • → Skill（外化专家经验）

Skill 把资深设计师的判断步骤写成可复用流程，替代每次重写的 Prompt。

类比框架

  • LLM ≈ CPU（算力）
  • Harness / Agent 平台 ≈ OS（调度）
  • Skill ≈ Application（专项工作流）
  • MCP ≈ 驱动/接线口（读写设计稿）

设计师语言对照表

Skill
可复用的「设计专家上岗手册」：规定何时触发、走哪些步骤、输出什么、何时停下。
MCP
让 AI 直接读写设计稿的「接线口」，能操作图层、变量、组件，而不只是导出 PNG。
Agent
接收目标、判断步骤、调用工具的执行主体；Skill 是被 Agent 按需加载的专项流程。
Design Token
颜色/字号/间距等设计变量；成熟工具（Adot、MasterGo）已支持 AI 读取与应用。
IDE
开发者写代码用的工具环境，类似设计师的 Figma 工作台；常见如 VS Code、Cursor。Pencil 把设计画布做进这类工具里，设计和代码同屏协作。
D2C
Design to Code，即设计稿转前端代码；Adot、MasterGo 均公开此能力。
.pen 文件
Pencil 的设计源文件，和代码放在同一个 Git 仓库管理；AI 经 MCP 直接读写，减少设计稿和代码不同步。

04

从设计师角度看：能做什么，还差什么

这里不排谁好谁坏，只对照各平台公开的能力，看它们覆盖了设计师工作流的哪些环节。

能力已成形、可用

  • 可编辑设计稿：Adot、Figma First Draft、MasterGo AI 快搭、Pencil .pen 文件均产出可编辑图层
  • 设计系统对接：Adot 变量/组件库 MCP；MasterGo 调用企业 Design System；Pencil 支持 Design System / Style Guide
  • 代码交付：Adot D2C、MasterGo D2C Pro、Google Stitch、Pencil MCP 导出 HTML/React
  • Agent 编排（多为公测/EA）：Adobe Firefly AI Assistant、字节 TRAE Work Design 模式已能演示「对话即设计」，但稳定性仍待验证

仍在快速演进

  • Skill 生态：标准已确立，但设计类 Skill 数量与质量仍在早期
  • MCP 云端版：Adot MCP 目前需桌面客户端；云端 MCP 仍在开发中
  • 新产品仍在早期：TRAE Work Design 模式、Pencil、Google Stitch 仍处 Early Access / Labs，稳定性与团队接入成本待验证
  • 跨工具一致性：生成稿与品牌规范、组件库的自动对齐仍依赖人工精修
  • 评测与治理：团队级 Skill 版本、权限、回归测试尚无行业通用方案

对专业设计师的意义

  • AI 负责快速出初稿，设计师负责判断和精修，角色更偏审核
  • 和企业设计系统、MCP 打通的工具，比普通生图工具更难被替代
  • 把经验整理成 Skill 比每次重写 Prompt 更有长期价值，不过目前还在早期

横向对比：不只是腾讯在做

把腾讯放到整个市场里，对照各厂商公开的能力和短板，都附来源链接。最右列「成熟度段」的定义见下框。

成熟度段怎么读？

与开篇「一页全景」中的三段标尺同一套归纳：按各平台在设计师工作流上的公开能力归类，非 Gartner 等第三方评级。

阶段 1 · 概念期 聊天式 Prompt 试玩；输出多为不可编辑图片；无团队规范与复用。本表未列入此类纯生图工具。
阶段 2 · 工具期 文生 UI / 图生 UI / 局部编辑；可编辑设计稿出现；仍偏单点任务，Agent / Skill / MCP 未成型或较弱。
阶段 3 · 工作流/资产期 Skill 固化专家流程；MCP 读写设计稿；生成—精修—验证闭环；D2C 与代码交付；可对接设计系统。

阶段 2→3：已经具备工具期的核心能力（可编辑稿 / 生 UI），但 Agent 编排、Skill 生态或 MCP 链路还在 beta、Early Access 或补齐中。表里 Figma、Stitch、TRAE Work、Pencil 等多属此类。

需要冷静看待：阶段 3 目前更多是「能力到位」，还不是「生产可用」。 把各家的宣传口径和它们自己公布的产品状态放在一起看，差距比较明显：
  • 宣传说「正式可用」，实际多在测试阶段。Adot 仍在公测，Firefly AI Assistant 公测，Figma Agent 还是 beta，Google Stitch 属于 Labs 实验项目，TRAE Work Design 和 Pencil 都还在 Early Access。真正稳定、能直接投入生产的并不多；MasterGo、即梦已经商用，但覆盖的能力范围比较窄。
  • 演示里的完整流程，换个环境未必跑得通。比如 Adot MCP 目前只支持 macOS 桌面端，云端版还没上线。换一套系统或企业流程，从生成到交付的链路就容易断；能跑通演示，不代表团队能日常使用。
  • 「把经验沉淀成 Skill 资产」还停留在设想阶段。Skill 的标准已经有了，但设计类的 Skill 数量少、质量参差；团队怎么管理 Skill 的版本、权限和测试，行业里也还没有成熟做法。
  • 真正的工作量还在设计师身上。AI 生成的稿子要对齐品牌规范和组件库，基本还得人工调整。AI 主要省的是起稿的时间，把关和修改这部分省不掉。
所以表里标的「阶段 3」或「2→3」，指的是这些产品已经走在这个方向上，不代表已经做到位。对团队来说，现在适合投入精力了解方法、积累能力，但不建议只凭厂商宣传就大规模投入预算或改造现有流程。

行业共识：Agent Skills 已成标准方向

OpenAI、Anthropic 均已发布官方 Skills 目录与创建规范；SkillHub 提供版本化 ZIP 分发与安全报告。 设计类 Skill 的价值不只是改文字或生图，更多在于把判断流程固定下来， 例如约定行业判断的优先级、复用组件做变体校验等（参考 Adot 官方 Skill 示例）。 这是多家厂商共同在做的方向，不是某一家的单独尝试。
